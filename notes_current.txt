...The word you are looking for is Macro-task (or simply an asynchronous event loop task).
|
When you call setTimeout, the JavaScript engine cannot just set a variable; it must register an event handle with Electron's underlying C++ event loop (libuv).
When a user types 60 words per minute, calling clearTimeout and setTimeout on every single keystroke creates heavy macro-task churn.
|

|
Here are the three ways to debounce with setTimeout, ranked from slowest to most optimal.
|
Comparison of Debounce Strategies
|
Strategy                            | Performance Characteristics                                                              | CPU / Event Loop Overhead
------------------------------------------------------------------------------------------------------------------------------------------------------------------
1. Destructive (Clear/Set)          | Destroys and recreates a macro-task on every single keystroke.                           | High (High macro-task churn)
2. Coalesced (Timestamp Check)      | Timer runs to completion. Spreads macro-task creation to once every 2500ms.              | Medium (Periodic overhead)
3. Persistent (State-Driven Re-use) | One timer is created once on the first keystroke, then updates pure variables in memory. | Ultra-Low (Zero macro-task churn)
|
The Most Optimal Way: The Persistent Reusable Timer
|
Instead of destroying the timer, or letting it expire and spawning a new one, you let a single timer live continuously as long as the user is typing.
|
When a key is pressed, you update a pure memory timestamp in your INTS array. The background timer ticks predictably, looks at that timestamp,
and dynamically reschedules itself only when necessary by adjusting its internally managed frame, rather than being deleted by the main thread.
|
Even better for a high-performance app: you can make it completely zero-allocation by managing a simple state flag.
|

    if (BYTES[byteEDI_cursor_is_paused] === 0) return;

    // Calculate how long the user has been silent in pure memory math
    const timeSinceLastInput = performance.now() - INTS[fEDI_lastInputTimestamp];

    // Have they been quiet for 2.5 seconds?
    if (timeSinceLastInput >= 2500) {
        // YES: Clear states and execute the payload
        BYTES[byteEDI_cursor_is_paused] = 0;

        EDI_cursor_cursorElement.style.animationPlayState = 'running';
